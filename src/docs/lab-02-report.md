# Главная страница React-приложения с mock-загрузкой и первыми хуками

| Параметр | Значение |
|----------|----------|
| **Проект** | «Трекер тренировок» — учёт и мониторинг физической активности. |
| **Лабораторная** | №2. Главная страница, mock-данные и первые хуки React. |
| **Ветка** | main |
| **Стек** | React, TypeScript, Vite, CSS. Backend и Redux не используются. |

## 1. Цель работы
Доработать первую главную страницу приложения «Трекер тренировок»: создать вёрстку, получить данные через mock-функцию, сохранить их в состоянии React, вывести список тренировок и показать отдельное состояние загрузки.

## 2. Выполненная работа
| Требование ЛР2 | Реализация в проекте |
|----------------|----------------------|
| Сверстать главную страницу | Создан общий layout с шапкой (Header), основной областью со сводкой и списком карточек. |
| Использовать mock-данные | Функция `fetchWorkouts` возвращает Promise и имитирует задержку сервера через `setTimeout` (1.5 сек). |
| Применить useState | В состоянии хранятся тренировки (`workouts`) и признак загрузки (`isLoading`). |
| Применить useEffect | После открытия страницы запускается загрузка mock-данных один раз (пустой массив зависимостей `[]`). |
| Вывести данные | Карточки тренировок строятся из массива через `map`; сводка считается через `filter` и `reduce`. |
| Разделить на компоненты | Используются `Header`, `WorkoutList`, `WorkoutCard` с передачей данных через props. |

**Границы текущей работы.** Навигация, React Router, backend, Redux и формы в ЛР2 не используются.

## 3. Структура главной страницы
• Шапка приложения с названием проекта и подзаголовком.
• Заголовок «Общая сводка» с расчётными показателями.
• Карточки со статистикой: всего тренировок, завершено, общее время.
• Блок «Все тренировки» со списком карточек.
• В каждой карточке: название, описание, категория, длительность и статус (Завершена / Запланирована).

## 4. Mock-данные вместо сервера
Файл `src/data/mockApi.ts` содержит функцию `fetchWorkouts`. Она возвращает Promise, ждёт 1500 миллисекунд и отдаёт массив `mockWorkouts`. Задержка нужна, чтобы состояние загрузки было заметно в интерфейсе.

## 5. Использование useState и useEffect
| Хук | Назначение | Пример в App.tsx |
|-----|------------|------------------|
| `useState` | Хранит данные, которые меняются во время работы компонента. | `workouts`, `isLoading` |
| `useEffect` | Запускает побочный эффект после отображения компонента. | `fetchWorkouts()` при открытии страницы |

В `useEffect` передан пустой массив зависимостей `[]`, поэтому mock-запрос выполняется один раз после открытия страницы.

## 6. Компоненты и передача props
Компонент `WorkoutList` получает через props массив тренировок `workouts` и выводит их. Компонент `WorkoutCard` получает одну тренировку `workout` и отображает её данные.

```tsx
<WorkoutList workouts={workouts} />

```
<WorkoutList workouts={workouts} />


## 7. Последовательность работы страницы
• При первом отображении `workouts` пустой, а `isLoading` равен `true`.
• Пользователь видит заголовок «Загрузка данных...».
• `useEffect` запускает `fetchWorkouts`.
• После Promise вызывается `setWorkouts(data)`, затем `isLoading` переключается в `false`.
• React повторно отображает компонент и показывает статистику и список карточек.
